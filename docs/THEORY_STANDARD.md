# AI Lab — стандарт интерактивной главы

AI Lab не должен превращаться в цепочку вопросов и мини-тестов. Вопрос, гипотеза и когнитивный конфликт нужны для того, чтобы создать потребность в новом знании. После открытия ученик обязательно получает связное объяснение, визуальную модель механизма, разобранный пример и три полноценных уровня углубления.

## Порядок внутри урока

**QUESTION → HYPOTHESIS → CONFLICT → DISCOVERY → THEORY → VISUAL MODEL → WORKED EXAMPLE → OPEN THE HOOD → ENGINEER → RESEARCHER → TRANSFER → BUILD MyAI**

Это один причинный маршрут. Математика, код и исследование не являются тремя отдельными курсами: они показывают одно и то же понятие на разных уровнях представления.

## 1. Обязательный Core Theory layer

После основного discovery-эксперимента каждый урок раскрывает полноценную теоретическую главу. Она содержит:

1. **Вводный мост** — связывает результат эксперимента с новым понятием.
2. **3–5 смысловых разделов** — не набор фактов, а причинное объяснение механизма.
3. **Словарь** — 2–5 новых терминов с короткими определениями.
4. **«Не перепутай»** — типичная ошибка или неверная интуиция.
5. **Главную мысль** — одно утверждение, которое ученик должен унести из урока.

## 2. Visual model — педагогическая иллюстрация

У каждого урока должна быть мини-схема, которую можно исследовать по узлам.

Она не декоративна. Каждый узел отвечает на один вопрос:

- что входит в механизм;
- что с этим происходит;
- что получается на выходе;
- где находится ограничение или точка выбора.

Ученик нажимает на узел и получает короткое объяснение его роли. Для разных тем это могут быть pipeline, граф вычислений, flow данных, матрица, распределение вероятностей, training loop или сравнительный профиль.

## 3. Worked example — разобранный пример

После теории ученик проходит пример **пошагово**, а не видит готовый ответ целиком.

Минимум 3 шага:

- исходная ситуация;
- промежуточные преобразования;
- результат и объяснение, почему он получился.

Если тема математическая, шаги содержат реальные подстановки и вычисления. Если концептуальная — последовательность рассуждения и контрпример.

## 4. Открой капот · математика и механизм

Это не «сложный текст для сильных». Это второй способ увидеть тот же механизм.

Обязательные элементы:

1. **Главная формула или формальное представление**.
2. **Расшифровка каждого символа**.
3. **Расчёт руками** минимум в 2 шага.
4. **Связь формулы с интерактивным экспериментом**.
5. **Объяснение внутреннего механизма**: что реально меняется, что остаётся неизменным и почему это работает.

На ранних темах математика может быть простой: булева логика, вектор признаков, число комбинаций. По мере курса она естественно доходит до loss, производной, gradient descent, матриц, softmax и вероятностных моделей.

## 5. Engineer · Code

Engineer не может состоять из фразы «попробуй написать код».

Каждый урок содержит:

1. **Инженерную цель** — что именно реализуем.
2. **Starter code**, в котором отсутствует содержательная часть.
3. **2–4 checkpoints** — что ученик должен понимать в коде.
4. **Проверяемый пропуск / challenge**.
5. **Подсказку после неудачной попытки**.
6. **Эталонное решение**, которое можно открыть.
7. Требование **объяснить строку своими словами**, а не только получить зелёную галочку.

Код должен постепенно складываться в `MyAI`, а не быть независимыми задачами.

## 6. Researcher · Experiment

Researcher — это маленький настоящий эксперимент, а не вопрос «что будет, если...?».

Обязательный протокол:

1. **Исследовательский вопрос**.
2. **Минимум две гипотезы** до запуска эксперимента.
3. **Независимая и зависимая переменные**.
4. **Пошаговая процедура**.
5. **Наблюдения / измеряемый результат**.
6. **Вывод**, который сопоставляется с исходной гипотезой.

Позже сюда добавляются ablation studies, сравнение learning rates, размеров моделей, tokenizers, context lengths, attention variants и системных оптимизаций.

## 7. Transfer

После всех объяснений ученик получает новую ситуацию без пошаговой подсказки. Transfer проверяет, переносится ли знание за пределы примера урока.

## Что запрещено

- задавать пять вопросов подряд без объяснения;
- считать правильный выбор в карточке доказательством понимания;
- заменять теорию одной фразой «главная мысль»;
- вводить термин до того, как ученик увидел проблему, которую термин решает;
- делать мини-схему декоративной иллюстрацией без смысловой функции;
- называть «Engineer» готовый код, который ученик только читает;
- называть «Researcher» вопрос без гипотезы, переменных, процедуры и наблюдений;
- прятать всю содержательную часть только в optional Deep Dive.

## Критерий качества

После урока ученик должен уметь:

1. **объяснить понятие своими словами**;
2. **показать механизм на схеме**;
3. **пройти разобранный пример без подсказки**;
4. **воспроизвести основную математику руками**;
5. **дописать ключевой фрагмент кода**;
6. **поставить маленький эксперимент и интерпретировать результат**;
7. **применить знание к новой ситуации**.

Если хотя бы несколько из этих пунктов отсутствуют, перед нами ещё не полноценная интерактивная глава AI Lab.
